# Zark roadmap: what to improve and how

Known limitations and planned work are tracked in GitHub Issues (labels `bug`, `soundness`, `crash`, `miscompile`, `diagnostics`, `docs`, `platform`, `speed`). The roadmap below explains *how*; the issues carry the repros and acceptance criteria.

Ordered by payoff. Each item says *how*, not just *what*.

## 0. Separate semantic analysis from code generation
Expression typing, calls, generics and statements are still interleaved with IR emission in `gen*.zk`; layouts already live in `sema_types.zk` and generic bodies are checked in `sema_check.zk`, but there is no typed AST. The next step is the layering from DESIGN.md Phase 3: `parse -> sema (typed AST) -> lowering -> backends`.
- **sema** resolves every expression to a type, checks calls, returns and assignments, and instantiates generics; it never prints IR.
- **lowering** turns the typed AST into the existing IR, and later into a real MIR for the native backend (item 2).
- Diagnostics, the LSP and new backends then read one checked tree, and a change to the type rules no longer touches the emitter.
- Keep the fixed points and the compile-time budget (no more than +10% on `bench/w.zk` and `selfhost/main.zk`).

## 1. Native backend: generated code quality (safe builds are ~1.5–2x slower than gcc -O0)
- **Dead blocks and short encodings (done).** Blocks that no branch can reach are dropped before register allocation (the frontend keeps emitting into a fresh block after a terminator), and `cmp $0, r` is emitted as `test r, r` and a zero constant as `xor r, r`. This shrinks the compiler built with the native backend by 1.4% with no change in instruction count.
- **Overflow check as one `jo` (done).** A checked signed `+`/`-` was `add` + `xor` + `xor` + `and` + `icmp slt ..., 0`; the `add` already sets OF, so the backend now recognises that exact chain and emits a single `jo` to the cold block (the `xor`/`and`/`icmp` are dropped). `fib` 57 -> 50 instructions, `sieve` 306 -> 272 (-11%), and CPU time on `bench/runtime.sh` -4% (min of 6 pinned runs; the median suggests more but this box is noisy). The three temporaries are only dropped when each is read exactly once, so any value that is used elsewhere keeps the explicit check; unsigned checks are untouched because they are already one `icmp`. Only 64-bit operations qualify: for `i8`/`i16`/`i32` the backend extends to 64-bit registers, so the flag would not fire, and the first version of this peephole silently lost the check on `i32` (caught by `tests/panics/add_overflow.zk`); narrower types keep the sign trick.
- **Mem2reg (tried, reverted, with numbers).** Promoting a scalar `alloca` to SSA values, then to `phi` at joins, was implemented in the native backend and measured. It removes the alloca, its stores and its loads, and it does cut code: `fib` 57 -> 52 instructions, `sieve` 306 -> 294, `mov` count in the compiler -4.7%. But speed did not follow: on CPU time (10 runs, pinned, `rusage` of the child, which excludes descheduling) the compiler itself went *up* by 1.5-2%, and the microbenchmarks moved by +-2% in either direction depending on the run. Two causes: (1) the backend already promotes a short-lived `alloca` to a register, so there is little left to win, and (2) a promoted value lives across calls, which costs one of the five callee-saved registers, and `mov reg, reg` is free on x86 while reusing the register for the result lengthens the dependency chain. A `phi` made it much worse (the sieve went from 739 ms to 1843 ms) because a `phi` result lives in a frame slot while the alloca it replaced was in a register. The code is in `c164fd9` for whoever picks this up again; the ordering that matters is coalescing first (phi and its incoming value in one register, moves on the edges), then mem2reg.
- **What the allocator needs first.** A fallback that reloads a call-crossing value from its incoming slot instead of pinning a callee-saved register for the whole function, and a spill heuristic that weighs a use inside a loop against a use across a call. Until then, keeping locals in allocas (which the backend already puts in registers when it can) is the better representation for this backend.
- **Where the native optimizer stands (settled for this round).** The cheap local transforms are already in and verified in the emitter, not assumed: `cmp $0` -> `test`, zero -> `xor`, `jo` for the checked add/sub, dead-block pruning, lazy aggregate slots, and `load_op`/`store_res` already skip a `mov` when the value is in the right register. What remains is not a peephole list. Every value lives in a frame slot, a call clobbers the five caller-saved registers, and the linear scan has no spill heuristic that prefers a loop value over a call-crossing one. mem2reg and `phi` were implemented and measured *slower* (numbers above), and `mov` count is not the bottleneck on x86. The next real step is the in-memory IR of item 2 plus a coalescing allocator; stacking more passes on the text IR is the ordering that already failed twice.
- **Linear-scan register allocation** over the IR the native backend already parses: live ranges are trivial to compute because values are SSA, and there are about 9 free registers (rbx, r12–r15 callee-saved; r8–r11).
- **Range facts (done, growing).** `if (n < 2) { return; }` proves `n >= 2` for the rest of the block, and `for i in lo..hi` proves `lo <= i < hi`, so the overflow check on `n - 1` / `i - 1` is dropped where it cannot fire. Facts are keyed by the declaration scope and the block that proved them, and are dropped on assignment, on `&x`, on capture, and whenever the name is shadowed. Facts carry both bounds, so `n + 1` after `if (n > 100) { return; }` is unchecked too. Next: `*` (needs both bounds in range), relational bounds (`i < len` from `for i in 0..s.len`) to drop `__oob`, and per-label facts so `if (i >= 0) { ... }` helps inside the arm, not only after an early exit.
- **Peephole optimizations.** Keep track of which value is in rax and skip the reload when the next instruction uses it. Turn `cmp + setcc + test + jcc` into a direct `jcc`. Encode small immediates as imm8.
- Expected gain: 1.5–2x on call-heavy code (the current `bench/runtime.sh` gap to gcc -O0), with no measurable cost in compile time. `-O --release` already uses LLVM and is close to clang -O2; this item is about the default, dependency-free backend.

## 2. Drop the textual IR on the native path
Today the frontend prints LLVM IR text and the native backend parses it back. `zark build selfhost/main.zk --time` (a 370k-line module) says: frontend ~290 ms, native backend ~220 ms, link ~230 ms. Inside the backend (shares from instrumenting a build, so they are relative): parsing the text is 42%, building live intervals 15%, the linear scan 2%, assigning slots 14%, instruction selection 27%. So the parse is worth about 90 ms of a ~740 ms native build — real, but the frontend is still bigger. **Measured outside the in-memory IR:** the `;@L` marker is parsed once per instruction through the checked `parse_int_radix`; replacing it with an inline digit loop moved the native backend by -0.4% (min of 5 interleaved runs, median +7.9%, i.e. noise). The cost is spread over slicing, map lookups and allocation, not number parsing, so it needs the IR change rather than micro-optimization. An in-memory IR (a list of structs) that is either printed as `.ll` (LLVM path) or lowered directly (native path) removes the parse and is the base for our own passes: constant folding, DCE, inlining small functions. Measure this box interleaved: the governor ramps, and the first run after an idle period is 2.5x slower than the rest, which is enough to invent a win that is not there.

## 3. Own linker and libc-free runtime → zero external tools for pure Zark
- Write a static ELF executable directly (`.text/.data/.bss` + `_start`). Our object writer already has 90% of this; the remaining part is laying out segments and resolving relocations ourselves.
- `rt.zk` on Linux syscalls: `write`, `mmap`, `exit`, `clock_gettime`, `open/read`, plus our own `printf` subset (the format strings are already built at compile time).
- Linking takes about 40 ms today, so this saves those 40 ms and the clang dependency. The system `ld` remains only for `.c/.cpp` interop.

## 4. Release builds
- Emit `noinline` for very large functions or long call chains (the inliner blow-up in the benchmark), or run our own pass pipeline (`opt -passes=...`) instead of `-O2`.
- **`llvm.*.with.overflow` (tried, reverted).** Emitting `llvm.sadd/smul/ssub.with.overflow` for the LLVM path gives `add` + `jo` in the machine code and three IR instructions instead of five. Measured interleaved it changes nothing: the run time is the same (466 vs 470 ms on fib), the frontend is the same (~290 ms), and clang takes the same 17.2 s on the compiler. The compiler contains only about 1260 checked operations, so the IR they add is 0.7% of the module, not the third a cold-cache measurement suggested. Not worth a second IR shape.
- **What `-O` costs, and why the level stays `-O2`.** On the 372k-line compiler module clang takes 19.4-20.2 s at `-O2` (two interleaved rounds), 15.5-17.1 s at `-O1` (-18%) and 2.6-2.9 s at `-O0` (-85%). A compiler built with `-O1` runs a full native build within 1% of the `-O2` one (min of 5 interleaved runs: 751 vs 744 ms), so the 4 s saved once would be paid back in user builds, and `-O0` is not an option. The 20 s is clang optimizing 2208 functions, not driver overhead: the runtime object is cached and the link is 90-170 ms. A smaller IR (item 2) is the lever, not another `-O` level.
- **A safe build cannot use the accumulator rewrite, and that is semantic (settled).** In `-O --release` LLVM turns `fib(n) = fib(n-1) + fib(n-2)` into a loop with an accumulator: `vb.fib` has one recursive call plus an add in the loop. In `-O` it keeps two recursive calls and the check (three calls in the disassembly, the third is `__ovf`). The check is not a pass that failed to fire: the rewrite reassociates the additions, and with checked overflow the order matters, because `(a + b) + c` may wrap twice and produce a valid result where `a + (b + c)` panics, or the reverse. Keeping the per-addition panic therefore forbids the reassociation. `llvm.sadd.with.overflow` does not change this (it is still a branch after the call; measured neutral earlier). Measured interleaved on the runtime benchmark: fib(38) 86 ms in `-O --release` vs 169 ms in `-O` (min of 5). The supported ways to get the fast shape are `--release` (checks removed by definition) and `+%`/`-%` on an expression where the author guarantees no overflow.
- Once item 1 lands, LLVM receives SSA instead of allocas and spends less time in SROA/mem2reg.

## 5. Parallel and incremental compilation
- Code generation per function is independent: spread the backend over threads (`pthread_create` through `extern`), one ELF section per thread, merged at the end.
- Cache per module: content hash → `.o` in `.zark-cache`; only modules that changed are recompiled.

## 6. Language
Done: closures with explicit captures, `T: Ord` constraints (checked at the call, not inside the generic body), `match` as an expression, `?T` and `orelse`, modules (`import "x.zk" as x`). Labeled `break`/`continue` are done.
- **Closures with an explicit context:** `fn[ctx](x: i64) i64`, lowered to a {fn, ctx} pair, with no hidden allocation (the context lives where the caller says).
- **Interfaces as generic constraints:** `fn sort[T: Ord](s: []T)`, checked when the generic is declared instead of when it is instantiated, which gives clearer errors.
- **More `comptime`:** reflection over struct fields and generated declarations (basic `comptime` expressions and static assertions are done).
- **Modules / namespaces:** `import "net.zk" as net`, then `net.connect(...)`.
- **SIMD types**: done through LLVM (`f32x4`, `i32x8`, ...). Missing: vector instructions in the own backend, comparisons and masks, shuffles.
- **Overflow checks** in safe mode (`add` + `jo` → panic), removed by `--release`.
- **Async cancellation and channels.** Cancellation is done and every future has `cancel()`: calling it runs the `defer` and `errdefer` of the active scopes immediately (innermost first), cancels the awaited child, and makes the frame finished. `Executor.deinit` cancels each live task exactly once, `select` cancels the loser, `join` cancels only the side that has not produced a value, and `block_on` cancels its future on `error.Deadlock`/`error.SystemCall`. A cancelled task is released like a detached one. Channels and `select_recv` are done: an unbounded FIFO with `close()` and `error.Closed`, waking only live receivers. Still missing: a multithreaded executor and an async channel shared between threads (`std/thread` has the blocking one).

## 7. Tooling
Done: `zark lsp` (language server), `zark test`, `zark fmt` (token based: it keeps comments and line breaks), compile errors with the source line, a caret and "did you mean" hints.
- `zark fmt`: the parser already exists; add a printer for the AST.
- `zark test`: `test "name" { ... }` blocks collected and run by the driver.
- DWARF line tables from the native backend: done (`break file:line`, `next`, `bt`). `-g` adds variables, structs and arrays (`print x`, `info locals`). Missing: unions, location lists for register variables, and any debug info on the LLVM path.
- Diagnostics are pinned: every `tests/errors/*.zk` has a `.err` file with the expected first non-empty message, and `tests/run.sh` compares it (the readable `error: ...`, with the file and line stripped). Missing method hints were added (`l.pus` now says `did you mean 'push'?`), and `cannot assign: target is const` now says how to fix it.
- Invariants: `tests/fmt_idem.sh` formats every `.zk` twice (same bytes) and compares `zark ir` before and after (266 files); `tests/determinism.sh` compares `zark ir` across two runs and with `ZARK_JOBS=1`; `tests/docs.sh` executes every `zark run` block in the guide, normalizes crash addresses and fails when `docs/` is stale; `tests/scale.sh` fails if `zark ir selfhost/main.zk` takes more than 15 s (`ZARK_MAX_SELFHOST_MS`). All four run from `tests/run.sh`.
- Ownership fuzzer: `tools/fuzz_own.py` generates pairs of correct and known-wrong programs (defer/deinit, move into a function, reassign after a move, clone, swap, branches and loops with consumption, borrows, closures, struct literals, overwriting an owned value, `*p` copies, returning a local pointer). The good program must print `ok`; the bad one must fail with the matching ownership diagnostic. 300 pairs are clean (no false errors, no accepted wrong programs); `--quick` runs 20 in `tests/run.sh`.
- Sanitizers: `tools/build_asan.sh` builds the self-hosted compiler from `build/stage2 ir` with AddressSanitizer and UndefinedBehaviorSanitizer. The whole `tests/run.sh` and the `fuzz_prog`/`fuzz_crash`/`fuzz_lsp` quick and sampled runs are clean under them (leaks are off because the compiler uses arena allocators; `tests/scale.sh` and `tools/fuzz_crash.py` lift their address-space limits for ASan). The sanitizer run found and we fixed the LSP caret-line panic (#72).
- Crash fuzzer: `tools/fuzz_crash.py` mutates every `.zk` in examples/tests/std/selfhost (delete/duplicate/swap a token or line, insert a bracket, truncate, replace an identifier with a keyword) and runs `zark tokens`, `zark ir` and `zark fmt --check` with a timeout and an address-space limit, using a stable copy of the compiler. It found and we fixed the unterminated-interface hang (#68), the empty-interpolation panic (#69), `?` in deferred code (#70) and `return`/`break`/`continue` in deferred code (#71). 100,000 mutations are clean; `--quick` runs 50 of them in `tests/run.sh`.
- LSP fuzzer: `tools/fuzz_lsp.py` speaks JSON-RPC to `zark lsp` with mutated documents (`didOpen`/`didChange` plus `hover`/`completion`/`definition`) and checks that every request is answered without a crash or hang; 2,000 sessions are clean, and `--quick` runs 20 in `tests/run.sh`.
- Differential whole-program fuzzer: `tools/fuzz_prog.py` builds random expression trees over i8-u64/f32/f64/bool (checked `+ - *` when the model proves no overflow, wrapping otherwise, `/` and `%` with truncation toward zero, arithmetic and logical shifts, boundary values including u64 above 2^63), structs of random shape (nested, arrays, by value and by pointer, returned by value), unions with `match`/`_`, enums, nested blocks with `defer`/`errdefer`, loops with `break`/`continue`, and `match` in a closure in a loop. A Python model computes the expected checksum and printed order, so a frontend bug shared by all backends is caught too; each program is built with native, `--llvm`, `-O` and `--release`, and divergences are delta-minimized. The fuzzer was mutation-tested (flipped defer order, `<` lowered as `<=`, shifted field offset, signed `>>` lowered as logical - all caught). 10,000 programs (seeds 1-10000) match the reference, and `--quick` runs 20 of them in `tests/run.sh`.

## 8. Platforms
An aarch64 backend (Raspberry Pi, ARM laptops) and Windows (PE/COFF + Win64 ABI). The lowering structure in `native.zk` stays the same; only the encoder and the ABI change.

## 9. FFI
Done: C headers (`import "x.h"`, `zark cbind`), the C ABI for structs, unions, variadics and arm64, and layer 4, C++ headers (`import "x.hpp"`: classes, methods, overloads, templates and the `std::string`/`std::vector`/`std::unique_ptr` shims through generated C++ shims; SPEC section 8).
Deferred from layer 4:
- **Subclassing C++ classes from Zark** and overriding virtual functions. One way is a generated C++ subclass whose overrides call Zark `fn` pointers with a context pointer.
- **Exceptions as `!T`.** Today a C++ exception aborts with a message. An opt-in error mode (a manifest key or a `cbind` flag) would map it to an error value.
- **Overload resolution for C++.** Overloaded functions and methods currently get automatic suffixes (`Begin`, `Begin_1`), which is workable for a small header and painful for a large library. Resolve an overload by the argument types at the call, and fall back to the suffix only when the language cannot decide (for example a function pointer or a template argument).
- **Direct calls by mangled name** for C-shaped signatures, with an `extern` that takes a link name, instead of going through a shim.
- **Lambdas and `std::function`** crossing into C++. Only plain `fn` pointers do today.
- **An `instantiate` key in `zark.toml`** to ask for template specializations without a wrapper `.hpp`.
- **Cross targets and macOS CI for C++ headers.** Only the aarch64 Linux bindings of one header are compared in tests, and the `std::` shims are not checked against libc++.
- **Rejecting a bitwise copy of a non-trivial C++ object** (soundness). `auto x = *p;` on a non-trivial C++ object still compiles and copies the bytes; a resource copied through a pointer, an array element or a field of a value is not tracked. Only copies through a variable name are moves today. The ownership pass has to treat any value of a non-trivial bound type as a resource: a copy is an error, a move is allowed, and `deinit` is required on every path out.
