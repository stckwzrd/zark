# async, await and a scheduler Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `async`/`await` compiled to state machines, a single-threaded executor with a timer and a TCP socket, and the ownership checks around them.

**Architecture:** Milestone 1 builds the runtime with hand-written futures (`Poll<T>`, `Context`, `Waker`, `Executor`, epoll/kqueue reactor in `std/rt.c`) and fixes the protocol. Milestone 2 teaches the parser and `gen` to turn `async` functions into a frame struct plus a `poll` function, as plain IR. Milestone 3 adds the checks in `gen_move.vibe`.

**Tech Stack:** Vibe (`selfhost/`, `std/`), C in `std/rt.c`, bash tests in `tests/run.sh`.

**Spec:** `docs/superpowers/specs/2026-11-22-async-design.md`

## Global Constraints

- Both fixed points hold after every task: `stage2 == stage3` and `native2 == native3` (`./bootstrap.sh`).
- New syntax or builtins reach `selfhost/` in two steps (CLAUDE.md invariant 2): teach the compiler, run `./bootstrap.sh`, `tools/update-seed.sh`, commit the seed; only then use the feature. The same rule applies to every new `vrt_*` symbol used from `std/` or `selfhost/`: add it to `std/rt.c`, bootstrap, update the seed, commit, and only then call it.
- The compiler knows no std names except the protocol list in SPEC section 6; `tests/no_magic_names.sh` must stay green.
- No hidden allocations: memory only through an explicit `Allocator`.
- No new IR instructions; the native backend has no `switch` (dispatch is an `icmp`/`br` chain) and supports alignment up to 16.
- Every task ends with `VIBE=build/vibe tests/run.sh` green, and edge tests also with `FLAGS=--llvm`.
- Linux and macOS (epoll and kqueue); no Windows. CI (`.github/workflows/ci.yml`) must stay green on all jobs.
- No comments in code (user rule); commit messages are one short imperative line.

## Review Focus

- A wake-up that arrives before the task returned `Pending` must not be lost (task wakes itself, or a fd is already readable): test in Task 3.
- `await` inside a loop that runs 100000 iterations must not grow the frame or leak: Task 7.
- An error returned with `?` through three nested awaits reaches the top as the same `error.X`: Task 7.
- 10000 spawned tasks complete and the executor's memory returns to the allocator (`DebugAllocator` reports no leak): Task 3.
- A peer that closes the connection while a read is pending yields `error.Closed`/end of stream, not a hang: Task 4.

### Task 3: executor, timer and JoinHandle

**Files:**
- Create: `std/async.vibe`
- Modify: `selfhost/loader.vibe` (`const auto STD_ASYNC = embed("../std/async.vibe");` and `"<std>/async.vibe" => return STD_ASYNC;` in `std_source`, and the module list in the "no standard module" message)
- Test: `tests/std/async.vibe`

**Interfaces:**
- Consumes: Task 1 types, Task 2 `vrt_poller_*`.
- Produces (module `std/async`, imported as `async`):
  - `struct Executor { static !Executor init(Allocator a); void deinit() move; !JoinHandle<T> spawn<F, T>(F fut); !T block_on<F, T>(F* fut); }` where `F` has `Poll<T> poll(Context* cx)`.
  - `struct JoinHandle<T> { bool done(); T take(); }`
  - `struct Sleep { static Sleep after(Executor* ex, i64 ms); Poll<void> poll(Context* cx); }` (void result modelled as `Poll<bool>` if `Poll<void>` is not expressible; the builder picks and uses the same type everywhere)
  - `struct Readable { static Readable on(Executor* ex, i32 fd); Poll<bool> poll(Context* cx); }` and `Writable` likewise.
  - Tasks are stored with a header `{ void* frame; fn(void*, Context*) -> bool poll_thunk; i32 state; }`; `spawn<F,T>` copies the not-yet-started future into task memory from the executor's `Allocator` and instantiates the thunk that writes the result into the task's slot; `block_on` takes a pointer because the future lives in the caller.

- [ ] **Step 1: failing tests** in `tests/std/async.vibe`:
  - `test "block_on drives a hand-written future"`: a struct `Countdown { i64 n; }` whose `poll` wakes itself and returns `Pending` until `n == 0`, then `Ready(42)`; `block_on` returns 42. (Self-wake before returning `Pending` must not be lost.)
  - `test "sleep orders tasks by deadline"`: three `spawn`ed `Sleep`-then-push tasks with 30, 10, 20 ms push to a shared list; the list is `[10, 20, 30]` order.
  - `test "ten thousand tasks"`: spawn 10000 `Countdown{3}` tasks with a `DebugAllocator`, `block_on` a future that waits for all, then `dbg.deinit()` reports no leak.
- [ ] **Step 2:** fail (`std/async` not found).
- [ ] **Step 3:** implement. Run queue: `List<*Task>`; timer heap: binary heap over `(deadline_ns, task)` using `now_ns()`; the loop runs ready tasks, computes the wait timeout from the next deadline, calls `vrt_poller_wait`, wakes tasks by token. `Waker.wake_fn` pushes the task to the run queue (single thread, no lock).
- [ ] **Step 4:** tests pass; `./bootstrap.sh` green.
- [ ] **Step 5:** commit "add the async executor".

### Task 6: frame and poll lowering, straight-line code

**Files:**
- Create: `selfhost/gen_async.vibe` (frame struct, `poll` function, `await` lowering)
- Modify: `selfhost/gen.vibe` (on-demand generation when a call needs a frame type; `types_out` completion), `selfhost/gen_call.vibe` (calling an async function returns the frame by value), `selfhost/gen_expr.vibe`, `selfhost/gen_stmt.vibe` (locals become frame fields inside an async body; `return` stores the result and returns `Ready`)
- Test: `tests/edge/async_basic.vibe`, `tests/expected/edge_async_basic.out`, `tests/run.sh` (add `async_basic` to the `edge` list)

**Interfaces:**
- Consumes: `std/async` (`Executor`, `block_on`) from Milestone 1.
- Produces: for `async T f(P1 a, P2 b)` a struct type named per instance containing `i32 state`, the arguments, all locals and temporaries, the result slot and one slot per awaited child; an IR function `Poll<T> poll(Frame* f, Context* cx)`; the call `f(x, y)` evaluates to the frame by value with `state = 0`. `await e` follows the position rule of the spec (statement, declaration initializer, assignment right side, `return` operand, `if`/`while`/`match` scrutinee, optionally followed by `?` or `catch`).

- [ ] **Step 1: failing test** `tests/edge/async_basic.vibe`: `async i64 add(i64 a, i64 b) { return a + b; }`, `async i64 chain() { auto x = await add(1, 2); auto y = await add(x, 10); return x * y; }`, a leaf future `Yield1` that returns `Pending` once (and wakes itself) then `Ready`, `async i64 with_yield() { await Yield1{}; return 5; }`; `main` runs each under `block_on` and prints `3`, `39` (x=3, y=13), `5`, and `sizeof(chain())` greater than 0.
