Установка и первая программа

Zark распространяется как исходный код: компилятор написан на самом Zark, поэтому его нужно один раз собрать с помощью цепочки начальной загрузки. Дальше он собирает сам себя и дорабатывается на себе же.

#Что понадобится

Что Зачем Версия
clang линковка готовых бинарников, сборка .c/.cpp файлов, режимы -O/--release 18 или новее
git получить исходники любой
bash, gzip скрипт bootstrap.sh любые

Отдельный стартовый компилятор не нужен. В репозитории лежит «семя» (bootstrap/seed.ll.gz): компилятор Zark, записанный как LLVM IR. clang собирает из него первую версию, а дальше компилятор собирает сам себя.

#Сборка компилятора

git clone https://github.com/stckwzrd/vibe.git
cd vibe
./bootstrap.sh

Скрипт выполняет всю цепочку и проверяет результат:

  1. собирает из семени первый компилятор через clang, а им — stage1 из исходников selfhost/;
  2. строит stage2 — компилятор, собранный предыдущим, и stage3 — ещё раз; проверяет, что stage2 и stage3 побайтно совпадают (неподвижная точка);
  3. строит цепочку без LLVM: native1, native2, native3 и проверяет, что native2 == native3;
  4. прогоняет весь набор тестов собственным компилятором;
  5. копирует результат в build/zark.

Занимает около минуты. В конце вы увидите строку == done: build/zark is the self-hosted compiler.

Важно: если в скрипте что-то не сошлось (неподвижная точка нарушена, тест упал), он останавливается с кодом 1 и ничего не копирует в build/zark. Такой компилятор использовать нельзя.

#Положить zark в PATH

Самое простое — ссылка в каталог, который уже есть в PATH:

mkdir -p ~/.local/bin
ln -sf "$PWD/build/zark" ~/.local/bin/zark
zark        # покажет справку

Ссылка указывает на файл build/zark, поэтому после каждого ./bootstrap.sh новая версия подхватывается сама.

#Первая программа

Создайте файл hello.zk:

void main() {
    println("Hello, Zark!");
}
Вывод
Hello, Zark!

Запустите: zark run hello.zk. Компилятор прочитает файл, сгенерирует машинный код, слинкует исполняемый файл в .zark-cache/hello и сразу его запустит.

Что тут важно:

  • программа начинается с функции main; если её нет, получится библиотека, которую нельзя запустить;
  • println печатает аргументы и перевод строки; внутри строки {...} вычисляется выражение (интерполяция: см. строки);
  • каждый оператор заканчивается точкой с запятой, как в C++ (лексика).

#Команды

zark run   file.zk [extra.c|.cpp|.o ...] [-O] [-- аргументы программы]
zark build file.zk [extra.c|.cpp|.o ...] [-o выход] [-O] [--release]
zark test  file.zk [extra.c|.cpp|.o ...] [-O]
zark fmt   [--check] file.zk ...
zark ir    file.zk
zark tokens file.zk ...
zark lsp
Команда Что делает
run компилирует и сразу запускает; всё после -- уходит программе как аргументы
build компилирует и оставляет исполняемый файл в текущем каталоге (по умолчанию имя файла без .zk)
test запускает блоки test "..." { } (тесты)
fmt приводит файлы к единому стилю (инструменты)
ir печатает LLVM IR, который сгенерировал фронтенд
tokens печатает токены (удобно при отладке лексера)
lsp запускает языковой сервер для редактора

#Аргументы программы

Всё после -- попадёт в программу. Внутри доступны arg_count() и arg(i). Нулевой аргумент — путь к самой программе, как в C:

$ zark run args.zk -- a "b c"
hello, 3 args
arg 0: .zark-cache/args
arg 1: a
arg 2: b c

(args.zk — программа, которая печатает arg_count() и все arg(i).)

#Код выхода

  • void main() { ... } — код 0;
  • i32 main() { return 7; } — код 7 (zark run возвращает код программы);
  • !void main() { return error.Boom; } — печатает error: Boom в stderr и возвращает 1;
  • panic("...") и выход за границы массива — печатают сообщение вида panic: ... (файл:строка) и возвращают 1.

#Флаги компилятора

Флаг Что значит
(по умолчанию) собственный x86-64 бэкенд без LLVM: самая быстрая сборка
--native выбрать собственный бэкенд, даже если указан -O (тогда -O не действует)
--llvm LLVM-бэкенд без оптимизаций
-O LLVM -O2; проверки границ остаются
--release -O2 и проверки границ убраны
--no-safety убрать проверки границ, не включая оптимизации
--fast-math --fast плюс разрешение переставлять операции с дробными числами (fast у fadd, fmul и так далее, как -ffast-math): суммы и произведения могут векторизоваться, но результаты могут немного отличаться
--check-overflow проверяет +, - и * на переполнение даже в сборке --release (безопасная сборка всегда проверяет ваш код; прелюдия не проверяется)
--fast --release плюс допущение, что знаковое переполнение не происходит (nsw, как в C++): иногда быстрее на целочисленных циклах, но при переполнении поведение не определено
-g только свой бэкенд: держать каждую локальную переменную в памяти и описать её для gdb (print x, info locals); код медленнее
--time напечатать время фронтенда, бэкенда и линковки
-o имя имя выходного файла
-- ... аргументы для zark run

Время сборки маленькой программы выглядит так (значения зависят от машины):

$ zark build hello.zk --time -o t1
time: frontend 2.9 ms, native backend 0.3 ms, link 98.9 ms
$ zark build hello.zk --llvm --time -o t2
time: frontend 3.0 ms, llvm backend 0.1 ms, link 156.6 ms

Почти всё время уходит на линковку clang. Подробнее про выбор режима: инструменты.

#Что появляется на диске

  • .zark-cache/ в текущем каталоге: объектные файлы (имя.o для своего бэкенда, имя.ll для LLVM), .o внешних C-файлов и исполняемый файл для zark run. Каталог можно удалять в любой момент. Добавьте его в .gitignore.
  • при zark build исполняемый файл создаётся в текущем каталоге (имя файла без .zk, либо то, что задано через -o).

#Структура проекта

Для небольшой программы достаточно одного файла. Когда он вырос, разделите его на модули (модули):

проект/
  main.zk        # fn main, import "geometry.zk"
  geometry.zk
  util/
    strings.zk

Пути в import считаются от каталога файла, в котором написан import.

#Редактор

Для VS Code / code-oss есть расширение с подсветкой, ошибками прямо в редакторе, автодополнением и переходом к определению. Установка и настройка других редакторов описаны на странице инструменты.
