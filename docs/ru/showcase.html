Витрина: многопоточный трассировщик лучей

Здесь разобран examples/showcase/: небольшой трассировщик лучей на Vibe. Он читает сцену из JSON, рисует её на нескольких потоках и печатает картинку символами. Эту же программу использует тестовый набор компилятора: вывод проверяется на каждом бэкенде.

vibe run examples/showcase/main.vibe
vibe run examples/showcase/main.vibe -- --ppm scene.ppm
vibe test examples/showcase/main.vibe

Программа собирается через LLVM автоматически, потому что использует SIMD-векторы.

#Что где лежит

Файл Что показывает
vec.vibe структура Vec3 поверх SIMD-вектора f32x4, перегрузка операторов (+ - * и унарный -), конструктор, const-методы, дженерик clamp<T: Ord> и блоки test
scene.vibe interface Shape, которую две структуры реализуют без всяких объявлений, union Material с данными, опциональные ?Hit, загрузка сцены модулем std/json и ошибки !T
render.vibe дженерик Grid<T>, match по union, рекурсия для отражений, рабочие потоки с атомарным счётчиком строк и WaitGroup, замыкание с явным захватом и заворачивающий оператор *% в контрольной сумме
main.vibe Arena с defer, embed файла сцены, Writer поверх print, обработка ошибок через catch, аргументы командной строки и тесты всего конвейера

#Вектор на SIMD

struct Vec3 {
    f32x4 v;

    Vec3(f32 x, f32 y, f32 z) { v = f32x4(x, y, z, 0.0); }

    Vec3 operator+(Vec3 o) const { Vec3 r; r.v = v + o.v; return r; }
    Vec3 operator*(f32 k) const { Vec3 r; r.v = v * k; return r; }

    f32 dot(Vec3 o) const {
        const auto m = v * o.v;
        return m[0] + m[1] + m[2];
    }
}

v + o.v — это одна векторная инструкция. Литерал справа от оператора берёт тип параметра оператора, поэтому a * 2.0 работает с f32.

#Фигуры без наследования

interface Shape {
    ?Hit intersect(Ray r);
}

struct Sphere {
    Vec3 center;
    f32 radius;
    Material mat;

    ?Hit intersect(Ray r) { ... }
}

У Sphere и Plane есть метод intersect с одной и той же сигнатурой, поэтому указатель на любую из них превращается в Shape. В List<Shape> лежат обе, а вызов — один косвенный вызов через таблицу методов. На диспетчеризацию память не выделяется.

#Union с данными

union Material {
    Vec3 Diffuse;
    Vec3 Mirror;
    Vec3 Emissive;
}

match hit.mat {
    .Emissive(c) => return c;
    .Mirror(c) => { ... return shade(sc, bounce, depth + 1).mul(c); }

#Ошибки как значения

Чтение сцены возвращает !Scene. Отсутствующее поле, вектор неверной длины, неизвестная фигура и неверный JSON — каждое становится ошибкой, которую вызывающий может напечатать или проверить в тесте:

!Material read_material(json::Value* m) {
    const auto kind = m.get("kind").as_str()?;
    const auto color = read_vec(m.get("color"))?;
    if (kind == "diffuse") { return Material::Diffuse(color); }
    if (kind == "mirror") { return Material::Mirror(color); }
    if (kind == "emissive") { return Material::Emissive(color); }
    return error.UnknownMaterial;
}

#Потоки без скрытых выделений

!void render(Scene* sc, Grid<Vec3>* img, i64 workers) {
    auto next_row = thread::AtomicI64{};
    auto wg = thread::WaitGroup{};
    thread::Thread[8] pool;
    wg.add(workers);
    for (auto i : 0..workers) {
        pool[i] = thread::spawn([&sc, &img, &next_row, &wg]() -> void {
            while (true) {
                const auto y = next_row.add(1);
                if (y >= img.h) { break; }
                for (auto x : 0..img.w) { img.set(x, y, trace(sc, x, y)); }
            }
            wg.done();
        })?;
    }
    wg.wait();
    for (auto i : 0..workers) { pool[i].join(); }
}

Каждый поток берёт следующую свободную строку из атомарного счётчика, поэтому строки делятся честно, а картинка не зависит от числа потоков. Тест рисует сцену на 1 и на 6 потоках и сравнивает контрольные суммы.

#Упражнения

  • Добавьте фигуру Triangle: ей нужен только метод intersect.
  • Добавьте в union материал "glass" и посмотрите, какие match компилятор попросит дополнить.
  • Соберите с --check-overflow и убедитесь, что контрольная сумма с *% по-прежнему заворачивается намеренно.
