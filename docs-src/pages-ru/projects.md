Для начала хватает одного файла. Когда программа разрастается до нескольких файлов, кода на C или чужих библиотек, опишите её в `zark.toml`, и `zark run`, `zark build` и `zark test` будут работать без имени файла.

```sh
zark new hello        # hello/zark.toml, hello/src/main.zk, hello/.gitignore
cd hello
zark run              # компилирует src/main.zk и запускает
zark run -- --name me # аргументы после -- получает программа
zark build --release  # пишет build/hello
zark test             # блоки test из src/main.zk и из всех файлов в tests/
```

Команды ищут `zark.toml` в текущем каталоге и во всех каталогах выше, поэтому работают и из `src/sub/`. Файл, явно названный в командной строке (`zark run tools/gen.zk`), внутри проекта всё равно получает зависимости, исходники C и библиотеки проекта.

## `zark.toml`

```text
[package]
name = "app"
version = "0.1.0"
main = "src/main.zk"      # что компилируют run и build (по умолчанию src/main.zk)
lib = "src/lib.zk"        # что загружает `import "app"` в проектах, которые зависят от этого

[build]
sources = ["c/fast.c"]      # файлы C или C++, которые компилируются и линкуются
libs = ["ssl", "m"]         # линкуются как -lssl -lm
flags = ["-O"]              # флаги по умолчанию; командная строка добавляет свои
out = "build/app"           # куда zark build пишет программу (по умолчанию build/NAME)

[dependencies]
utils = { path = "../utils" }
json5 = { git = "https://github.com/someone/json5.zk", rev = "v1.2" }
```

Формат — небольшая часть TOML: секции, `key = value`, строки, целые, логические значения, списки, встроенные таблицы и комментарии `#`. Ошибка сообщается с номером строки: `zark.toml:2: error: unterminated string`.

## Зависимости

Зависимость импортируется по имени:

```zark fragment
import "utils" as u;            // lib-файл зависимости
import "utils/strings" as us;   // файл рядом с ним (.zk можно не писать)
```

- Зависимость `path` указывает на каталог на диске.
- Зависимость `git` клонируется в `.zark/deps/NAME`, когда она впервые нужна команде (`rev` — тег, ветка или коммит); если зависимость есть в `zark.lock`, дерево ставится на залоченный коммит.
- Зависимость со своим `zark.toml` приносит с собой свои зависимости, исходники C и библиотеки. Без манифеста её lib-файл — `src/lib.zk` или `lib.zk`.
- Импорты, начинающиеся с `./` или `../`, всегда относительные, поэтому имя зависимости их не заслоняет.

### Блокировка и обновление

Зависимость `git` записывается в `zark.lock` рядом с `zark.toml`: URL, запрошенный `rev` и точный коммит, в который он разрешился. `zark build`, `run`, `test` и языковой сервер используют этот коммит, поэтому сдвинувшаяся ветка или тег не меняет сборку.

```sh
zark update              # заново разрешить все git-зависимости и переписать zark.lock
zark fetch               # поставить залоченные коммиты в .zark/deps (без резолва; для CI и офлайна)
zark add URL [--rev R]   # добавить git-зависимость в zark.toml и залочить
zark remove NAME         # убрать зависимость из zark.toml и zark.lock
```

- `zark update` — единственная команда, которая двигает зависимость на новый коммит; она же заменяет запись, когда вы меняете `rev` в `zark.toml`.
- Если `zark.toml` просит `rev`, которого нет в `zark.lock`, или скачанное дерево не на залоченном коммите, сборка останавливается и просит `zark update`.
- Одно имя — один источник и один коммит: два разных `rev` или два разных git-URL для него — ошибка.
- Зависимости `path` не блокируются: их правят на месте.
- Коммитьте `zark.lock`: именно его собирают коллеги и CI.

Языковой сервер читает тот же манифест, так что импорты зависимостей находятся и в редакторе.
