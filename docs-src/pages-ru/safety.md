Zark — системный язык, поэтому он не может обещать того, что обещает язык со сборщиком мусора. Он даёт более узкое и честное обещание: **ошибка останавливается как можно раньше, пока компилятор её видит, а иначе — громко, с файлом и строкой, а не тихо портит память.** Эта страница перечисляет все случаи, чтобы вы знали, на что можно опираться.

## Режимы сборки

| Режим | Как | Проверки | Для чего |
|---|---|---|---|
| безопасный | `zark run`, `zark build` | всё, что ниже | разработка, тесты, большинство программ |
| безопасный и оптимизированный | `-O` | те же проверки, оптимизация LLVM | продакшен, когда проверки нужно оставить |
| без проверок | `--release` | убраны проверки границ, деления, переполнения и null | программа, уже прогнанная в безопасных режимах |
| голое железо | `--freestanding` | нет вспомогательных функций рантайма, значит нет проверок | ядра и драйверы |

Проверки при компиляции (типы, владение, утечки адресов) одинаковы во всех режимах. Различие только в том, что проверяется во время работы программы.

## Три исхода

Любая проблема заканчивается ровно одним из трёх способов.

1. **Ошибка компиляции.** Программа не собирается. Это лучший исход.
2. **Паника.** Программа сразу останавливается с сообщением, файлом и строкой (`panic: index 3 out of bounds (len 3) at main.zk:4`). Паника означает баг в программе, и её нельзя перехватить.
3. **Значение-ошибка.** Функция возвращает `!T`, и вызывающий решает, что делать. Это для того, что может случиться в правильной программе: нет файла, плохой ввод, нет памяти.

## Что и когда останавливается

| Ошибка | Что происходит |
|---|---|
| Не тот тип, преобразование с потерей, нет `as` | ошибка компиляции |
| Числовой литерал вне своего типа (`u8 x = 300`) | ошибка компиляции |
| Присваивание в `const` | ошибка компиляции |
| Выброшенный результат `!T` | ошибка компиляции |
| `match`, дающий значение, но пропускающий вариант | ошибка компиляции |
| Забытый вариант в операторе `match` | ничего не происходит (оператор может пропускать варианты) |
| Структура, содержащая саму себя, цикл алиасов, бесконечно растущий шаблон | ошибка компиляции |
| Использование переменной после `free`, `destroy`, `deinit`, `close` или `join` | ошибка компиляции |
| Двойное освобождение одной переменной | ошибка компиляции |
| Возврат или сохранение указателя или среза на локальную переменную | ошибка компиляции |
| Использование указателя или среза в `List` или `Map` после его изменения | ошибка компиляции |
| Изменение `List` или `Map` внутри цикла, который по нему итерирует (и идёт на следующий круг) | ошибка компиляции |
| Копирование ресурсного элемента по индексу-значению (`l[i]`, `List.get(i)`) | ошибка компиляции |
| Перенос или изменение элемента из `for` по контейнеру ресурсов | ошибка компиляции |
| `match` по ресурсной union с последующим использованием значения | ошибка компиляции |
| Раскрытие ресурсного optional или error union с последующим использованием | ошибка компиляции |
| `Thread`, не присоединённый на каждом пути, брошенный или возвращённый вместе с захваченной локальной переменной | ошибка компиляции |
| Ложное утверждение `comptime assert` | ошибка компиляции |
| Индекс или срез вне границ | паника |
| Целочисленное деление или остаток на ноль, или `MIN / -1` | паника |
| Переполнение целых в `+`, `-`, `*` | паника |
| Нет памяти, плохой ввод, нет файла | значение-ошибка |
| `List`, которому не дали аллокатор | значение-ошибка (`error.NoAllocator`) |
| Дробное, не помещающееся в целое (`1e30 as i32`) | насыщается до ближайшей границы, `nan` становится 0 |
| Сдвиг на слишком много бит | счётчик обрезается по ширине типа |
| Чтение переменной, которой ничего не присвоили | невозможно: переменные начинаются с нуля |
| Разыменование `null` или переполнение стека бесконечной рекурсией | программа останавливается с понятным сообщением и бэктрейсом |

В безопасном режиме ничто из этого списка не является неопределённым поведением. Одна и та же программа даёт один результат на нативном бэкенде, с `--llvm` и с `-O`, и тест в репозитории это поддерживает.

## Владение и заимствование без borrow checker

В Zark нет времён жизни и borrow checker, как в Rust. Есть кое-что поменьше, что можно выучить за десять минут и что ловит ошибки, случающиеся на практике. Оно следит за **переменными** внутри **одной функции**:

- Параметр или метод с пометкой `move` забирает значение. В стандартной библиотеке `move` стоит на `free`, `destroy`, каждом `deinit`, `join` и на `close` сокетов и потоков. После вызова переменная мертва, пока вы не присвоите ей значение заново.
- Метод с пометкой `borrows` возвращает указатель или срез внутрь объекта (`List.at`, `List.slice`, `Map.get_ptr`). Метод с пометкой `invalidates` может сдвинуть память (`push`, `put`, `insert`). Если вызвать метод `invalidates`, все указатели и срезы, взятые из этого объекта раньше, становятся мёртвыми.
- Указатель или срез на локальный массив или структуру не может покинуть функцию: ни через `return`, ни сохранением через параметр-указатель или в глобальную переменную.
- Цикл, который итерирует по контейнеру (`for (auto x : list)`, `list.slice()`, `this->items`), не может вызвать у него метод `invalidates` и пойти на следующий круг. Выходите через `break` или `return` сразу после изменения или итерируйте по копии. Нересурсный элемент копируется по значению; ресурсный — это невладеющая копия (ниже).
- Ресурсный элемент, прочитанный по индексу-значению (`l[i]`, `List.get(i)`), отвергается: проверка идёт по именам и постоянным путям, поэтому индекс-значение не отследить, и копия стала бы вторым владельцем. Постоянный индекс, укоренённый в локальной переменной, переносит этот путь. Внутри методов самого контейнера (`this->items[i]` в `pop`, `remove_at`, ...) чтение доверенное: только контейнер знает, жив ли слот.
- Ресурс, до которого добираются через указатель или срез (`this->l`, `hp->l`, `s[0]`, `(*p).l`), нельзя скопировать или перенести наружу: `auto y = this->l`, `return this->l`, `f(this->l)` и `take(this->l)` — ошибки компиляции, потому что копия стала бы алиасом памяти, которой всё ещё владеет указатель или контейнер. Поле или постоянный индекс локального значения (`h.l`, `l.items[0]`) переносится обычным образом. `Map.get` и `Map.get_or` для ресурсного значения отвергаются, как `List.get`; заимствуйте через `get_ptr(key)`.
- `for` по контейнеру ресурсов даёт невладеющую копию каждого элемента: её можно читать и вызывать её `borrows`-методы, но нельзя переносить (параметр `move`, `deinit`, ресурсное поле) и нельзя вызывать `invalidates`-метод у неё или у поля (`x.inner.push`), потому что заголовок копии изменился бы, а контейнер всё ещё указывает на старый буфер. Забирайте элемент через `pop`/`remove_at`/`swap_remove` или `move_out(&c[i])`. Замыкание не может его захватить: захват — это указатель на копию.
- `match (u)` по ресурсной union забирает `u`: привязка в arm владеет payload, а использование `u` после этого — ошибка. Внутри `for` по ресурсам привязка — невладеющая копия по тем же правилам, что и переменная цикла.
- `x orelse d` и `x catch d` копируют payload наружу, поэтому ресурсный optional или error union в месте потребляется раскрытием: использование `x` после — ошибка.
- Структура, объявленная `owned` (в стандартной библиотеке это `Thread`), должна быть использована в каждой области, где она живёт: присоединена, отсоединена, передана дальше или возвращена. Это включает выходы через `?`, поэтому пишите `defer t.join();` или `errdefer t.join();` сразу после создания. Бросить такое значение на месте нельзя.

Состояние отслеживается через `if`, `match`, `catch`, циклы, `defer` и `errdefer`. Проверка нарочно консервативна там, где иначе отвергала бы корректные программы, поэтому о том, чего она не видит, она молчит. Четыре вещи она не видит:

- **Копии.** `auto q = p; a.destroy(p); use(q)` не ловится.
- **Поля для `move`.** `a.free(this->data)` не помечает поле освобождённым. (Заимствования и `invalidates` пути полей вроде `this->items` учитывают.)
- **Другие функции.** Функция, которая освобождает переданное ей без пометки `move`, невидима.
- **Гонки данных.** Ничто не проверяет, что два потока не трогают одну память.

Свои функции можно пометить теми же словами, и проверка распространится и на них. См. [память](memory.md#использование-после-free-ошибка-компиляции).

## Закрываем пробел инструментами

То, что компилятор не может доказать, ловит инструмент во время тестов.

**`DebugAllocator`** даёт каждому блоку собственные страницы и делает освобождённый блок недоступным. Использование после освобождения, даже через копию указателя, останавливается на самом обращении с номером блока, а `deinit()` перечисляет всё, что не освободили.

```zark run exit
void touch(i64* p) { *p = 1; }

!void main() {
    auto dbg = DebugAllocator::init();
    const auto a = dbg.allocator();
    auto p = a.create<i64>()?;
    const auto copy = p;
    a.destroy(p);
    touch(copy);
}
```



```zark run exit
!void main() {
    auto dbg = DebugAllocator::init();
    const auto a = dbg.allocator();
    _ = a.create<i64>()?;
    _ = a.alloc<u8>(100)?;
    dbg.deinit()?;
}
```

Запускайте тесты с `DebugAllocator` в роли аллокатора. Поскольку функции получают аллокатор параметром, менять код для этого не нужно.

**`zark test`** запускает каждый блок `test`. **`-g`** добавляет информацию о строках и переменных для `gdb`. **Обработчик падений** печатает сигнал, причину (нулевой указатель, переполнение стека, использование после освобождения) и бэктрейс, а `ZARK_CRASH_HANDLER=0` отключает его, чтобы получить core-файл. См. [инструменты](tooling.md).

## Потоки

Замыкания захватывают переменные по указателю. Поток, переживший переменные, которые он использует, читает освобождённый стек. Правила:

1. Присоединяйте (`join`) каждый поток до того, как переменные, используемые его замыканием, выйдут из области видимости.
2. Защищайте общие данные через `Mutex`, используйте `AtomicI64` или передавайте значения через `Channel`.
3. Не копируйте `Mutex`, `Cond`, `WaitGroup` или `Channel`, когда они уже в работе. Делитесь ими через указатель.

Первое правило компилятор проверяет для `Thread` в переменной: он должен быть присоединён на каждом пути, включая неудачные (см. [потоки](net-threads.md)). Потоки в списке или массиве, гонки данных и порядок `join` он не видит. Пишите `join` рядом со `spawn`, как пишете `defer` рядом с выделением, и тестируйте с несколькими потоками.

## Чек-лист перед выпуском

- [ ] Все тесты проходят в безопасном режиме, а в тестах памяти стоит `DebugAllocator`.
- [ ] `zark build -O` проходит те же тесты.
- [ ] Каждый `+%`, `-%` и `*%` в коде стоит не зря (хеш, счётчик).
- [ ] Каждый `comptime assert`, охраняющий формат файла или раскладку, на месте.
- [ ] Только потом, если нужна скорость, соберите с `--release` и снова запустите тесты.
